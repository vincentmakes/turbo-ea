# Ваш первый анализ: Гармонизация приложений

Это и есть вознаграждение. У Вас есть инвентарь приложений, карта возможностей и встроенное поле Модель TIME. Теперь Вы соединяете их и создаёте два отчёта, которые оправдывают всю EA-программу перед CIO:

- Отчёт **«Портфолио приложений»**, в котором все приложения сгруппированы по **критичности для бизнеса** и окрашены по их **TIME**-диспозиции (**T**olerate / **I**nvest / **M**igrate / **E**liminate — Терпеть / Инвестировать / Мигрировать / Ликвидировать).
- **Карта возможностей** — тепловая карта, показывающая, где у Вас избыточность (несколько приложений на возможность) и хрупкость (одно приложение на возможность).

## Шаг 1 — сопоставьте приложения с возможностями

Единственная самая ценная связь во всей метамодели — это **Application → Business Capability** (`supports` / `is supported by`). Вы установите её для каждого приложения в области.

### Массовый путь: режим редактирования инвентаря

1. Перейдите в **Инвентаризация**, отфильтруйте по Type = `Application`.
2. Убедитесь, что столбец связи **Business Capability** виден (вкладка Columns → Relations).
3. Переключите режим **Редактирование таблицы** на панели инструментов.
4. Кликните по ячейке возможности на каждой строке и выберите одну или несколько возможностей. Каждое изменение сохраняется сразу же.

Для 50–200 приложений это занимает один день и одну чашку кофе.

### Путь карточка за карточкой

Для сопоставлений, требующих суждения (или когда вовлечён воркшоп с Владельцем приложения), откройте каждую карточку Приложения и используйте секцию **Relations**. Вы получите полный пикер с поиском, предпросмотром иерархии и возможностью устанавливать атрибуты связи.

### Сколько возможностей на приложение?

| Число сопоставлений | Что это означает |
|--------------|---------------|
| **0** | Не сопоставлено — Ваш инвентарь неполон. Отфильтруйте такие и исправьте. |
| **1** | Чистый, идеальный случай — это приложение поддерживает ровно одну возможность. |
| **2–3** | Нормально — многие приложения охватывают пару связанных возможностей. |
| **4+** | Подозрительно — Вы можете путать «использует данные из» с «поддерживает». Перепроверьте. |

!!! tip "Лучшая практика"
    Сопоставление первого прохода — быстрое и грубое. Второй проход — сделанный с участием Владельца приложения — делает данные заслуживающими доверия. Запланируйте оба.

## Шаг 2 — оцените критичность и пригодность

Три встроенных поля в разделе **Оценка** каждой карточки Application питают анализ. Заполняйте их вместе с Владельцем приложения — на часовом воркшопе Вы обычно можете оценить 30–50 приложений в режиме **Редактирование таблицы** с тремя видимыми столбцами.

| Поле | Опции | На какой вопрос отвечает |
|------|-------|--------------------------|
| **Критичность для бизнеса** | Критически важный / Критичный для бизнеса / Операционный / Административный | Насколько бизнес зависит от этого приложения? |
| **Функциональная пригодность** | Отлично / Подходящий / Недостаточный / Неприемлемый | Насколько хорошо оно делает то, что нужно бизнесу? |
| **Техническая пригодность** | Полностью подходящий / Адекватный / Неприемлемый / Неподходящий | Насколько здорова технология, лежащая в его основе? |

Критичность для бизнеса группирует отчёт на шаге 4. Две оценки пригодности — это то, что читает вычисление TIME на шаге 3.

Редактирование этих полей на согласованной карточке переключает её статус согласования в **Нарушен**. После воркшопа повторно согласуйте карточки пакетом.

## Шаг 3 — выведите TIME с помощью вычисляемого поля

Встроенное поле **Модель TIME** на Application (`timeModel`, четыре опции: `tolerate` / `invest` / `migrate` / `eliminate`) — это колонка решения, которая ведёт остальной анализ. Вместо того чтобы просить каждого Владельца приложения выбрать значение, выведите его из двух оценок пригодности с помощью **вычисления** — классическое размещение Gartner:

| | Техническая пригодность высокая | Техническая пригодность низкая |
|---|---|---|
| **Функциональная пригодность высокая** | **Инвестировать** | **Мигрировать** |
| **Функциональная пригодность низкая** | **Терпеть** | **Ликвидировать** |

1. Перейдите в **Админ → Метамодель → Вычисления** и нажмите **Новое вычисление**.
2. Задайте **Целевой тип карточки** = `Application` и **Целевое поле** = **Модель TIME**.
3. Вставьте формулу из [Кастомизируйте метамодель → Вариант: выводите поле автоматически с помощью Вычисления](customise-the-metamodel.md#option-derive-a-field-automatically-with-a-calculation). Она использует встроенные поля пригодности, поэтому пользовательское поле не нужно.
4. Нажмите **Проверить**, сохраните, затем используйте **Тест** на нескольких хорошо знакомых Вам приложениях, чтобы проверить результат.
5. Переключите вычисление в состояние **Активно** в списке, затем нажмите **Пересчитать все** в его строке, чтобы заполнить Модель TIME у каждого приложения.

С этого момента Модель TIME пересчитывается при каждом сохранении приложения, показывает бейдж **вычисляемое** и больше не редактируется вручную. Приложение без одной из оценок пригодности не получает значения TIME — это сделано намеренно: так видно, каких оценок ещё не хватает.

!!! warning "Don't"
    Вычисляемый TIME — это **стартовая гипотеза**, а не вердикт. Проверьте результаты с Владельцами приложений, прежде чем их представлять. Если решение должно отменить результат формулы, выключите вычисление (переключатель **Активно**) и отредактируйте Модель TIME вручную в режиме **Редактирование таблицы**.

Справочник: [Админ → Вычисления](../admin/calculations.md).

## Шаг 4 — запустите отчёт «Портфолио приложений»

1. Перейдите в **Отчёты → Портфолио приложений**.
2. Задайте **Группировка** = **Критичность для бизнеса**.
3. Задайте **Цвет приложений по** = **Модель TIME**.
4. Нажмите на значок закладки (**Сохранить отчёт**) и назовите представление («Портфолио приложений — домен Продаж»). Вы снова найдёте его в **Отчёты → Сохранённые отчёты**.

Каждый уровень критичности для бизнеса становится блоком, в котором у каждого приложения есть свой чип, окрашенный по его TIME-диспозиции, и полоса, показывающая соотношение. Чтобы сфокусироваться на одном домене, используйте фильтр **Связано через** с возможностями из Вашей области.

На что обратить внимание:

- **Критически важные и критичные для бизнеса приложения с отметкой «Мигрировать»** — Ваши самые значительные решения по модернизации. Они идут первыми.
- **Административные и операционные приложения с отметкой «Ликвидировать» или «Мигрировать»** — Ваши самые быстрые победы в упрощении: выведите их из эксплуатации или консолидируйте на другой платформе.
- **Критически важные приложения с отметкой «Инвестировать»** — убедитесь, что они действительно получают инвестиции.
- **Приложения без цвета** (TIME *Не задано*) — не хватает одной из двух оценок пригодности. Вернитесь к шагу 2.

Справочник: [Отчёты → Портфельный отчёт](../guide/reports.md).

## Шаг 5 — запустите Карту возможностей

1. Перейдите в **Отчёты → Карта возможностей**.
2. Оставьте **Метрика тепловой карты** на значении **Количество приложений**: интенсивность цвета ячейки пропорциональна количеству приложений, поддерживающих эту возможность.
3. Необязательно: включите **Показать приложения** и задайте **Цвет приложений по** = **Модель TIME**, чтобы увидеть TIME-диспозицию приложений внутри каждой возможности.

На что обратить внимание:

- **Горячие ячейки** (много приложений на возможность) — кандидат на избыточность. Самый распространённый бизнес-кейс для Рационализации портфеля приложений живёт здесь.
- **Холодные ячейки** с приложениями, которые Вы бы ожидали — пробелы в Вашем сопоставлении или действительно недо-поддерживаемые возможности.
- **Белые ячейки** посреди активной ветви — несопоставленные приложения или несмоделированные возможности.

Справочник: [Отчёты → Карта возможностей](../guide/reports.md).

## Шаг 6 — презентуйте и итерируйте

Теперь у Вас есть защитимое представление о портфеле. Поставьте два отчёта перед CIO по Продажам (или тем, кто владеет Вашей областью) и:

- Подтвердите TIME-решения по критически важным и критичным для бизнеса приложениям.
- Определите 3 самые горячие ячейки на тепловой карте как кандидатов в проекты рационализации.
- Зафиксируйте последующие действия как комментарии или todos на самих приложениях — Turbo EA отслеживает их по каждой карточке.

И всё. У Вас есть работающая EA-практика на Turbo EA.

## Что дальше

Когда Ваш портфель приложений жив и заслуживает доверия, эти модули становятся высокоценными следующими шагами. Ни один из них не полезен до того, как у Вас есть заполненный инвентарь — поэтому это руководство намеренно их отложило.

| Модуль | Когда его открывать | Где найти |
|--------|----------------|------------------|
| **Реестр рисков** | Когда Вы готовы отслеживать архитектурные риски против приложений и возможностей (TOGAF Phase G). | [Реестр рисков](../guide/risks.md) |
| **GRC / Compliance** | Когда нужно сопоставить приложения и возможности с регуляциями (GDPR, NIS2, EU AI Act, DORA, SOC 2, ISO 27001). | [GRC](../guide/grc.md) |
| **PPM** | Когда решения по рационализации становятся проектами с бюджетами, расписаниями и статус-отчётами. | [PPM](../guide/ppm.md) |
| **TurboLens AI** | Когда у Вас достаточно карточек, чтобы ИИ нашёл дубликаты поставщиков, кандидатов на модернизацию и архитектурные рекомендации. | [TurboLens](../guide/turbolens.md) |
| **BPM** | Когда Вы готовы моделировать процессы, лежащие поверх Ваших приложений. | [BPM](../guide/bpm.md) |
| **Diagrams** | Когда нужны свободные архитектурные диаграммы, остающиеся синхронизированными с инвентарём. | [Diagrams](../guide/diagrams.md) |
| **EA Delivery** | Когда Вы начинаете создавать TOGAF-документы Statements of Architecture Work и Architecture Decision Records. | [EA Delivery](../guide/delivery.md) |

Добро пожаловать в Turbo EA.
