# 您的首次分析：应用合理化

这就是回报所在。您已经有了一份应用清单、一份能力图谱，以及内置的 TIME 模型字段。现在将它们关联起来，产出两份报告，足以向 CIO 证明整个 EA 项目的价值：

- **应用组合**报告：所有应用按**业务关键性**分组，并按其 **TIME** 处置（**T**olerate 容忍 / **I**nvest 投资 / **M**igrate 迁移 / **E**liminate 淘汰）着色。
- **能力地图**：一张热力图，展示您在哪里存在冗余（一个能力对应多个应用）和脆弱性（一个能力仅由单一应用支撑）。

## 步骤 1——把应用映射到能力

整个元模型中最有价值的关系是 **Application → Business Capability**（`supports` / `is supported by`）。您将为范围内的每个应用都设置它。

### 批量路径：资产清单编辑模式

1. 进入**资产清单**，按 类型 = `Application` 过滤。
2. 确保关系列 **Business Capability** 可见（列标签页 → 关系）。
3. 在工具栏中切换到**表格编辑**模式。
4. 点击每一行的能力单元格，选择一个或多个能力。每次更改都会立即保存。

对于 50–200 个应用，这只需要一个下午和一杯咖啡。

### 逐卡片路径

对于需要较多判断的映射（或与应用负责人有工作坊的场景），打开每张 Application 卡片，使用**关系**分区。您将获得完整的选择器，包含搜索、层级预览以及设置关系属性的能力。

### 每个应用对应多少个能力？

| 映射数量 | 含义 |
|--------------|---------------|
| **0** | 未映射——您的资产清单不完整。过滤这些并修正。 |
| **1** | 干净理想的情况——该应用恰好支撑一个能力。 |
| **2–3** | 没问题——许多应用横跨几个相关能力。 |
| **4+** | 可疑——您可能把「使用其数据」与「支撑」混为一谈。重新核对。 |

!!! tip "最佳实践"
    第一遍映射快速而粗糙。第二遍——与应用负责人一起评审——才是让数据值得信赖的关键。请为两遍都做规划。

## 步骤 2——评定关键性与适配性

每张 Application 卡片**评估**分区中的三个内置字段为这项分析提供数据。请与应用负责人一起填写——在一小时的工作坊中，使用**表格编辑**并显示这三列，通常可以评定 30–50 个应用。

| 字段 | 选项 | 回答的问题 |
|-------|---------|-----------------|
| **业务关键性** | 关键任务 / 业务关键 / 业务运营 / 行政管理 | 业务对这个应用的依赖程度有多高？ |
| **功能适用性** | 完美 / 适当 / 不足 / 不合理 | 它满足业务需求的程度如何？ |
| **技术适用性** | 完全适合 / 足够 / 不合理 / 不适当 | 其底层技术的健康状况如何？ |

业务关键性用于在步骤 4 中对报告进行分组。两项适用性评级则是步骤 3 中 TIME 计算所读取的数据。

在已批准的卡片上编辑这些字段，会把其审批状态翻转为**已失效**。工作坊结束后，请分批重新批准这些卡片。

## 步骤 3——通过计算字段推导 TIME

Application 上的内置 **TIME 模型**字段（`timeModel`，四个选项：`tolerate` / `invest` / `migrate` / `eliminate`）是驱动后续分析的决策列。与其要求每位应用负责人各选一个值，不如通过**计算**从两项适用性评级推导出它——这就是经典的 Gartner 定位：

| | 技术适用性高 | 技术适用性低 |
|---|---|---|
| **功能适用性高** | **投资** | **迁移** |
| **功能适用性低** | **容忍** | **淘汰** |

1. 进入**管理员 → 元模型 → 计算**，点击**新建计算**。
2. 设置**目标卡片类型** = `Application`，**目标字段** = **TIME 模型**。
3. 粘贴[定制元模型 → 选项：通过计算自动推导字段](customise-the-metamodel.md#option-derive-a-field-automatically-with-a-calculation)中的公式。它使用内置的适用性字段，因此无需任何自定义字段。
4. 点击**验证**并保存，然后对几个您熟悉的应用使用**测试**，检查结果。
5. 在列表中将该计算切换为**活跃**，然后点击其所在行的**重新计算所有**，为每个应用填入 TIME 模型。

从此以后，每次保存应用时都会重新计算 TIME 模型，该字段会显示**计算值**徽章，并且无法再手动编辑。缺少任一适用性评级的应用不会获得 TIME 值——这是有意为之：它能告诉您哪些评级仍然缺失。

!!! warning "Don't"
    计算出的 TIME 是一个**起步假设**，而不是裁定结果。在呈报结果之前，请与应用负责人一起评审。如果某项决策必须推翻公式，请关闭计算（**活跃**开关），然后在**表格编辑**中手动编辑 TIME 模型。

参考资料：[管理员 → 计算](../admin/calculations.md)。

## 步骤 4——运行应用组合报告

1. 进入**报告 → 应用组合**。
2. 设置**分组依据** = **业务关键性**。
3. 设置**应用着色依据** = **TIME 模型**。
4. 点击书签图标（**保存报告**），为视图命名（「应用组合——销售领域」）。之后可以在**报告 → 已保存报告**中再次找到它。

每个业务关键性级别会成为一个方框，其中每个应用对应一个按 TIME 处置着色的标签，另有一条显示构成比例的条形图。如需聚焦某个领域，请使用**关联方式**筛选器，并选择您范围内的能力。

观察要点：

- **被标记为迁移的关键任务和业务关键应用**——您影响最深远的现代化决策。应优先处理。
- **被标记为淘汰或迁移的行政管理和业务运营应用**——您最快可以实现的简化成果：将它们退役，或整合到其他平台上。
- **被标记为投资的关键任务应用**——确认它们确实获得了相应投资。
- **没有颜色的应用**（TIME *未设置*）——两项适用性评级中有一项缺失。请回到步骤 2。

参考资料：[报告 → 投资组合报告](../guide/reports.md)。

## 步骤 5——运行能力地图

1. 进入**报告 → 能力地图**。
2. 将**热力图指标**保持为**应用数量**：单元格颜色强度与支撑该能力的应用数量成正比。
3. 可选：打开**显示应用**，并设置**应用着色依据** = **TIME 模型**，以查看每个能力内各应用的 TIME 处置。

观察要点：

- **热单元格**（每个能力对应多个应用）——候选冗余。应用组合合理化最常见的业务场景就在这里。
- **预期会有应用但呈现冷色的单元格**——映射缺失，或确实未被充分支撑的能力。
- **活跃分支中间的白色单元格**——未映射的应用，或未建模的能力。

参考资料：[报告 → 能力地图](../guide/reports.md)。

## 步骤 6——汇报并迭代

您现在已经拥有一份站得住脚的组合视图。把这两份报告呈给销售 CIO（或您范围的负责人），并：

- 对关键任务和业务关键应用确认 TIME 判断。
- 在热力图中识别前 3 个热单元格作为候选合理化项目。
- 把后续事项作为评论或待办记录到应用本身上——Turbo EA 会按卡片追踪。

就这么多。您已经在 Turbo EA 上拥有了一份可运作的 EA 实践。

## 接下来做什么

一旦您的应用组合活跃并受到信赖，以下都会成为高价值的下一步动作。在拥有填充好的资产清单之前，它们都不太有用——这就是本指南刻意推迟它们的原因。

| 模块 | 何时打开 | 在哪里找到 |
|--------|----------------|------------------|
| **风险登记册** | 当您准备好针对应用和能力跟踪架构风险时（TOGAF 阶段 G）。 | [风险登记册](../guide/risks.md) |
| **GRC / 合规** | 当您需要把应用和能力对照法规（GDPR、NIS2、欧盟 AI 法案、DORA、SOC 2、ISO 27001）进行映射时。 | [GRC](../guide/grc.md) |
| **PPM** | 当合理化决策转化为带预算、进度和状态报告的项目时。 | [PPM](../guide/ppm.md) |
| **TurboLens AI** | 当卡片数量足以让 AI 找到厂商重复、现代化候选与架构推荐时。 | [TurboLens](../guide/turbolens.md) |
| **BPM** | 当您准备好对位于应用之上的流程进行建模时。 | [BPM](../guide/bpm.md) |
| **图表** | 当您需要与资产清单保持同步的自由形式架构图时。 | [图表](../guide/diagrams.md) |
| **EA 交付** | 当您开始产出 TOGAF 风格的架构工作说明书和架构决策记录时。 | [EA 交付](../guide/delivery.md) |

欢迎使用 Turbo EA。
