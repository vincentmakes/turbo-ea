# Slack Notifications

您的团队本来就在 Slack 上办公。**Slack Notifications** 以 **Slack 私信**把每个人的
Turbo EA 通知发给本人——指派的待办事项、等待其签署的决策、落到其手上的风险——并附
带一个可直接返回卡片的按钮。

每个人都掌握主动权：在各自的通知偏好设置中，会出现一个与「应用内」和「邮件」并列的
**Slack** 列，由本人勾选究竟哪些通知类型经由 Slack 送达。**默认不开启任何一项。**

## 概览

| | |
|---|---|
| **许可** | 商业——需要已签名的许可授权 |
| **Turbo EA 最低版本** | 2.89.1 |
| **权限** | `ext.slack-notify.admin` |
| **数据访问授权** | `core.notifications.channel`、`core.users.read` |
| **是否需要重启后端** | 是——包含后端代码 |
| **出现位置** | **管理 → 设置 → 集成 → Slack** · 所有人[通知偏好设置](../guide/notifications.md)中的 **Slack** 列 |

只需要**出站访问 `slack.com` 的 HTTPS**——无需入站 URL、无需 OAuth 回调，也无需通过
Slack Marketplace 审核。正因如此，它在自托管或位于防火墙之后的实例上同样可用。

## 配置

打开**管理 → 设置 → 集成**并选择 **Slack** 子标签页。面板会引导您完成三个编号步骤。

### 1. 创建 Slack 应用

面板会显示一份现成的**应用清单（manifest）**。在 Slack 中选择 **Create New App →
From a manifest**，选定您的工作区，粘贴该清单（面板提供**复制清单**按钮），随后点击
**Install to Workspace** 并复制 **Bot User OAuth Token**——它以 `xoxb-` 开头。

该清单仅申请四个 bot 作用域，别无其他：

| 作用域 | 用途 |
|---|---|
| `chat:write` | 发送私信 |
| `im:write` | 与某人开启私信会话 |
| `users:read` | 读取成员目录 |
| `users:read.email` | 按邮箱把 Turbo EA 账户对应到 Slack 成员 |

!!! warning "请勿开启令牌轮换"
    该清单有意关闭了 Slack 的**令牌轮换**。一旦开启，bot 令牌每 12 小时就会过期，
    而本版本无法自动续期：投递将每天中断两次。

### 2. 连接工作区

| 字段 | 说明 |
|---|---|
| **机器人用户 OAuth 令牌** | `xoxb-…` 令牌。加密存储；之后留空即保留原令牌 |
| **Slack 消息中显示的名称** | 默认为 *Turbo EA*。用于消息按钮与页脚 |
| **将通知发送到 Slack** | 默认开启——这是暂停开关，而非安装步骤 |

点击**保存**，再点击**测试连接**；随后会出现 *Connected to …* 标签确认。

### 3. 关联人员

当某人首次需要接收消息时，系统会**按邮箱地址**进行关联，并缓存结果。**人员**卡片列
出所有人，问题最多的排在最前，并以标签标示谁**已连接**、**不在 Slack 中**或**尚未
检查**。

对于 Slack 地址与 Turbo EA 邮箱不一致的人，请填入其 **Slack 成员 ID**（形如
`U01ABCDEF`）并点击**保存**——手动关联始终优先于邮箱匹配。**发送测试消息**可端到端
验证关联是否有效。清空该字段会让此人重新回到邮箱查找。

Slack 不认识的人员会每天自动重试一次，因此先有 Turbo EA 账户、后加入 Slack 工作区
的人无需人工干预即可被覆盖。

!!! note "仅存储成员 ID"
    该扩展只存储 Slack 成员 ID，别无其他——邮箱地址始终留在 Turbo EA 中。

## 每个人自己掌控的部分

扩展运行后，所有人都会在自己的**通知偏好设置**中获得一个 **Slack** 列，与「应用内」
和「邮件」并列。

![通知偏好设置对话框中的「Slack」列](../assets/img/en/71_ext_slack_notification_preferences.png)

- **每种类型默认都是关闭的。** 在本人为某类型开启之前，谁都不会收到 Slack 消息。
- 表格下方的页脚会告诉每个人其账户是否已关联到 Slack，或者是否需要请管理员完成
  关联。
- 仅限应用内的升级公告绝不会投递到 Slack。

Turbo EA 决定存在哪些通知类型、谁开启了它们；扩展只负责传输消息。

## 消息长什么样

一条 Slack 私信包含加粗的通知**标题**、消息正文、一个 **Open in Turbo EA** 按钮
（使用您配置的名称）指向相关卡片或页面，以及一行标注应用名称与通知类型的小字页脚。

投递严格单向——由 Turbo EA 发往 Slack——且始终是个人私信。绝不会向频道发布任何内容。

## 监控投递

**投递日志**卡片显示有多少消息**等待中**、**已发送**与**失败**，并列出最近 50 条日
志。

消息进入队列后数秒内发出。若 Slack 限流或返回错误，扩展会以递增的间隔重试，六次之
后放弃；永久性失败——令牌被吊销、用户被删除、缺少作用域——会立即停止，而不做无谓的
重试。已投递的记录在 14 天后清理。

队列停滞恰好只有两种原因，面板会指出适用的那一种：

- **未存储机器人令牌**——粘贴令牌并保存。
- **投递已关闭**——重新开启*将通知发送到 Slack*。

**重试失败项**会把所有已放弃的消息重新入队，并重新检查 Slack 此前不认识的人员。这
是故障或更换令牌之后的恢复途径。

## 权限

| 权限 | 允许 |
|---|---|
| `ext.slack-notify.admin` | 配置工作区连接、关联人员、发送测试消息、查看投递日志并重试失败项 |

其他人完全看不到该子标签页。**终端用户无需任何额外权限**——他们只需在自己的通知偏好
设置中勾选即可。

## 许可证失效或扩展被停用时

投递会暂停，**Slack** 列从对话框中消失，但**所有设置与开启选项都会保留**。续期许可
证后投递即恢复。*将通知发送到 Slack* 开关同理：它在不卸载任何内容的前提下暂停投递，
排队的消息只是等待而已。

机器人令牌加密存储，并被排除在工作区迁移之外。

## 限制

- **仅限私信**——不会向频道发布。
- **没有交互式按钮。** 本版本不支持在 Slack 中直接执行「标记完成」或「批准」等操
  作；消息会链接回 Turbo EA。
- **没有摘要合并**——每条通知都是独立消息，而非打包汇总。
- **请勿开启 Slack 的令牌轮换**（见上文警告）。
