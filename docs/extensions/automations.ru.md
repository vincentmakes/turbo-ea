# Automations

Большая часть управления EA — это список того, что кто-то пообещал делать
вручную: завести риск, когда приложение без владельца переваливает за порог
затрат; напомнить техническому владельцу, когда компонент достигает окончания
поддержки; предупредить бизнес-владельца, когда редактируется утверждённая
карточка. Список верный; подводит исполнение — каждый пункт живёт напоминанием
в чьей-то голове, а не правилом, за которым следит платформа.

**Automations** превращает эти обещания в правила, которые Turbo EA выполняет
за вас. Правило целиком собирается из выпадающих списков — *когда* что-то
происходит в ландшафте, *если* выполняются условия, *то* выполнить действия, —
и каждый запуск записывается как пакет мутаций в Журнал аудита, так что
правило, которое сработало не так, отменяется одним щелчком.

## Кратко

| | |
|---|---|
| **Лицензия** | Коммерческая — требуется подписанное право |
| **Минимальная версия Turbo EA** | 2.126.0 |
| **Разрешения** | `ext.automations.view`, `ext.automations.manage` |
| **Гранты доступа к данным** | Карточки (чтение + запись), события карточек и задач, задачи (чтение + запись), каталог пользователей, риски (чтение + запись), записи решений, уведомления, роли заинтересованных сторон |
| **Нужен перезапуск бэкенда** | Да — расширение содержит серверный код |
| **Где появляется** | **Automations** в разделе **Администрирование** меню пользователя · чип с числом запусков на странице карточки |

## Правило: когда, если, то

![Таблица правил](../assets/img/en/86_ext_automations_rules.png)

Вкладка **Правила** перечисляет все правила с их триггером, типом карточки,
действиями, переключателем включения, последним запуском и кнопкой запуска.
Откройте любое, чтобы увидеть редактор.

![Редактор правила](../assets/img/en/87_ext_automations_editor.png)

Редактор вверху пересказывает правило простыми словами, а затем проводит по
его трём частям:

**Когда** — что запускает выполнение. Правило наблюдает за одним типом карточек
и срабатывает по одному из событий:

| Триггер | Срабатывает, когда |
|---|---|
| карточка создана / обновлена / архивирована / восстановлена | эта карточка меняется |
| связь добавлена / удалена | связь — при желании, заданного типа — затрагивает карточку |
| задача выполнена | закрыта задача, прикреплённая к карточке |
| по расписанию | наступает момент пятипольного cron-выражения (UTC) — тогда правило проверяет каждую карточку этого типа |

**Если** — условия в виде вложенных групп **все из** / **любое из**. Каждая
строка — поле, оператор и значение, выбранные из выпадающих списков:
собственные поля карточки и фазы жизненного цикла, её теги, её роли
заинтересованных сторон (*никем не занята*, *занята*…), её связи, статус
окончания поддержки у Приложений и ИТ-компонентов, а для триггера *карточка
обновлена* — что именно **изменилось**, чтобы правило срабатывало только при
переходе значения из одного состояния в другое. Оставьте группу пустой, чтобы
правило выполнялось для каждой карточки.

**То** — действия, выполняемые по порядку. Неудавшееся действие останавливает
запуск, а строка запуска сообщает, какой шаг не удался.

| Действие | Что делает | Требует |
|---|---|---|
| Установить / очистить поле, задать дату жизненного цикла, подтип, родителя, название или описание | Редактирует карточку | запись в инвентарь |
| Установить теги | Заменяет, добавляет или убирает теги с учётом групп с единственным выбором | запись в инвентарь |
| Создать связанную карточку, добавить связь | Добавляет карточку другого типа и связывает её либо связывает две существующие карточки | запись в инвентарь |
| Архивировать карточку | Архивирует её (восстановима в течение 30 дней) | запись в инвентарь |
| Назначить / снять роль заинтересованной стороны | Выдаёт роль человеку, обладателю роли, обладателю роли на родительской карточке или тому, кто вызвал срабатывание правила | роли заинтересованных сторон |
| Создать задачу | Задача на карточке для исполнителя, со сроком | задачи |
| Уведомить людей | Уведомление в приложении / по почте согласно собственным настройкам получателей | уведомления |
| Завести риск, обновить риск | Регистрирует риск в Реестре рисков с категорией, вероятностью и влиянием, привязанный к карточке и с владельцем; последующий запуск может обновить его заголовок, владельца или целевую дату | риски |
| Оформить черновик решения | Черновик записи архитектурного решения (ADR), привязанный к карточке, — правило никогда его не подписывает | записи решений |
| Вызвать вебхук | Подписанный HTTPS-запрос во внешнюю систему с карточкой, сведениями об изменении и правилом | — |
| Стоп | Завершает список действий | — |

Заголовки, описания и сообщения — это шаблоны: `{{card.name}}`,
`{{card.attributes.costTotalAnnual}}`, `{{actor.name}}`, `{{change.old}}` и
подобные подставляются для каждой карточки, а редактор предлагает переменные
из меню.

Под действиями находятся два параметра. **Срабатывать один раз на карточку**
(включён по умолчанию) запоминает, для чего правило уже сработало, поэтому
ночное правило не заводит один и тот же риск каждую ночь; оно сработает снова,
когда изменятся значения, которые оно читает. **Ночная сверка** перепроверяет
каждую карточку в 03:00 UTC, так что пропущенное событие исправляется само.

## Симуляция и «Запустить сейчас»

**Симулировать** прогоняет правило по всем карточкам его типа в режиме
предпросмотра — ничего не записывается — и показывает, сколько карточек
подходит и, для каждой карточки, что именно сделало бы каждое действие. При
включении правила, которое ни разу не симулировалось, вас попросят сначала
выполнить симуляцию; включить его можно и без неё.

**Запустить сейчас** делает то же самое по-настоящему: правило немедленно
срабатывает для каждой подходящей карточки, соблюдая *срабатывать один раз на
карточку*, если вы не отметите *сработать снова для уже обработанных
карточек*. Диалог результата показывает, что было сделано, карточка за
карточкой, и ссылается на пакет аудита.

![Результаты запуска](../assets/img/en/88_ext_automations_run_results.png)

## Запуски и Журнал аудита

![Вкладка запусков](../assets/img/en/89_ext_automations_runs.png)

Каждый запуск — строка на вкладке **Запуски**: какое правило, на какой
карточке, как он начался (событие, расписание, ночная сверка, «Запустить
сейчас»), чем закончился и каждая строка действий. Фильтруйте по правилу или
результату; собственное число запусков карточки показано чипом на её странице.

Каждая запись, которую делает запуск, попадает в **Администрирование →
Настройки → Журнал аудита** как пакет расширения с пособытийными различиями.
**Сканирование** — расписание, ночная сверка или «Запустить сейчас» — это
**один пакет на все карточки, для которых оно сработало**, поэтому правило,
которое сработало не так, — это один **Откат**, а не по одному на карточку.
Откат отменяет записи карточек и связей, а начиная с Turbo EA 2.127.0 — и
риски, которые запуск завёл или изменил, назначенные им роли, установленные
теги и оформленные черновики решений. Задачи и уведомления намеренно остаются
на месте — просьбу к человеку и доставленное сообщение не отменить их
удалением, — и предпросмотр отката говорит об этом до того, как что-либо
применяется.

## Уведомления группируются

Правило никогда не отправляет по уведомлению на каждую карточку. Сканирование
собирает, что причитается каждому человеку, и в конце отправляет **одно**
уведомление на человека и правило: одна карточка приходит отдельным
сообщением, несколько — сводкой с перечнем карточек, заголовок которой вы
задаёте в действии (*Заголовок сводки*). Изменения, приходящие одно за другим
— импорт, затронувший триста карточек, — отправляют первое уведомление сразу,
а остальные удерживают на время **окна группировки** из Настроек; в следующую
минуту накопившееся уходит одной сводкой. Собственные настройки уведомлений
каждого человека по-прежнему решают: колокольчик, почта или канал расширения.

## Шаблоны

Вкладка **Шаблоны** — галерея готовых правил: дорогое приложение без
владельца, окончание поддержки в ближайшие 180 дней, новое приложение без
бизнес-способности, отредактированная утверждённая карточка, низкое качество
данных в течение месяца, приложение, входящее в фазу вывода из эксплуатации,
карточка, архивированная с открытыми связями, инициатива, становящаяся
активной, критичное приложение без технического владельца, зарегистрированный
новый поставщик, ИТ-компонент с истёкшей поддержкой. Каждый открывается в
редакторе выключенным, чтобы вы подстроили его и симулировали.

| Настройка | Что делает |
|---|---|

## Демонстрационные данные

**Загрузить демонстрационные данные** в Настройках устанавливает шаблоны и три
показательных правила на примерном ландшафте, включает большинство из них и
однократно запускает несколько, чтобы вкладкам «Правила», «Запуски» и Журналу
аудита было что показать. **Удалить** забирает ровно это обратно — правила,
запуски, созданные ими задачи и риски.

## Разрешения

| Разрешение | Даёт |
|---|---|
| `ext.automations.view` | Видеть правила, их запуски и галерею шаблонов, а также чип с числом запусков на карточках |
| `ext.automations.manage` | Создавать, редактировать, включать, симулировать, запускать и удалять правила; менять настройки; загружать демонстрационные данные |

## Если лицензия истекла или расширение отключено

Страница исчезает из меню, расписания останавливаются, а события больше не
рассылаются. Ничего не удаляется: правила, их запуски и всё, что они записали,
— карточки, риски, задачи, решения — остаются ровно как есть. Продление
лицензии или повторное включение расширения возвращает правила, по-прежнему
включёнными.

## Замечания и ограничения

- Turbo EA разрешает расширению 60 аудируемых пакетов в минуту. Сканирование
  очень большого инвентаря приостанавливается на этом пределе и продолжается
  на следующем тике; «Запустить сейчас» сообщает об этом в результате, а
  следующее сканирование подхватывает оставшиеся карточки.
- Правило, наблюдающее за *карточка обновлена*, видит только изменения,
  сделанные после его включения; для существующего ландшафта используйте
  «Запустить сейчас» или дождитесь ночной сверки. Условия на то, **что
  изменилось**, срабатывают только на живых обновлениях.
- Вебхуки — только HTTPS, подписываются секретом экземпляра, никогда не
  следуют перенаправлениям и обрываются по таймауту через 10 секунд; ответ
  записывается в запуск.
- Правило может обновлять только те риски, которые само завело, и никогда не
  может подписать решение, перевести риск в другой статус или выполнить
  задачу — это остаётся за человеком.
