# Jira Todo Sync

不必再维护两份任务清单。**Jira Todo Sync** 把 Turbo EA 的待办事项镜像到您选定的
Jira Cloud 项目，并让两边保持一致：在 Turbo EA 中创建的待办事项会在几秒内成为一个
Jira 事务，完成它会把该事务流转为「完成」；符合您所设过滤条件的 Jira 事务则会显示
为待办事项。标题、截止日期与负责人双向同步。

## 概览

| | |
|---|---|
| **许可** | 商业——需要已签名的许可授权 |
| **Turbo EA 最低版本** | 2.68.0 |
| **权限** | `ext.jira-todos.admin` |
| **数据访问授权** | `core.todos.read`、`core.todos.write`、`core.events.todo`、`core.users.read` |
| **是否需要重启后端** | 是——包含后端代码 |
| **出现位置** | **管理 → 设置 → 集成 → Jira Todo Sync** · 待办事项页面与卡片待办标签页上的事务编号标签 |

仅支持 **Jira Cloud**。连接是纯出站的——Turbo EA 使用账户邮箱与 API 令牌调用 Jira
的 REST API。无需暴露 OAuth 回调，无需安装 Jira 应用，也不需要入站网络访问，因此在
自托管或位于防火墙之后的实例上同样可用。

## 配置

### 1. 创建 Atlassian API 令牌

1. 访问 <https://id.atlassian.com/manage-profile/security/api-tokens>，使用同步应
   当以其身份操作的 Atlassian 账户登录。如有条件请使用**专用服务账户**——事务将以
   该账户创建和流转。（此直达链接是可靠途径；令牌页面已无法通过显眼的菜单路径
   到达。）
2. 点击 **Create API token**——选择普通的那一个，**不要**选 *Create API token with
   scopes*。**不支持带作用域的令牌。**
3. 为其命名（例如 `turbo-ea-sync`）并选择有效期。Atlassian 要求必须设置，且上限为
   **一年**。
4. **立即复制该令牌**——它只显示一次。

!!! warning "令牌会过期"
    令牌过期后，同步会因认证失败而停止，直到填入新令牌为止。创建时请记下到期日期。

### 2. 连接 Turbo EA

打开**管理 → 设置 → 集成**，选择 **Jira Todo Sync** 子标签页。

在 **Jira Cloud 连接**中填写：

| 字段 | 说明 |
|---|---|
| **站点 URL** | 例如 `https://your-site.atlassian.net` |
| **账户邮箱** | 令牌所属的 Atlassian 账户 |
| **API 令牌** | 加密存储。之后留空即保留已保存的令牌 |

点击**测试连接**。成功时会显示 *Connected as …*。

### 3. 设定范围

在**同步范围**中：

- **Jira 项目**——从列表中选择，该列表在连接信息填好后即从 Jira 加载。推送出去的
  待办事项将在此创建为 **Task** 类型的事务。
- **拉取过滤器(JQL)**——符合该 JQL 的事务会被镜像为待办事项。留空则使用默认值
  `project = "<KEY>" AND statusCategory != Done`。
- **轮询间隔(秒)**——多久查询一次 Jira。默认 300，最小 60。

**方向**下有三个开关：

| 开关 | 默认 | 作用 |
|---|---|---|
| **推送待办事项到 Jira** | 开 | 在 Turbo EA 中创建的待办事项成为 Jira 事务；完成待办事项会流转其事务 |
| **从 Jira 拉取事务** | 开 | 匹配的 Jira 事务显示为待办事项；解决事务会完成对应的待办事项 |
| **镜像签署待办(单向)** | **关** | 风险、决策与项目的签署会成为带回链的 Jira 事务，但仍必须在 Turbo EA 中完成 |

点击**保存配置**。**立即同步**会马上执行一轮。

负责人映射无需配置——Turbo EA 会按邮箱地址自动把人员对应到 Jira 账户。

## 同步行为

| 事件 | 效果 |
|---|---|
| 在 Turbo EA 中创建待办事项 | 数秒内创建一个 Jira 事务（标题、含回链的描述、截止日期、负责人） |
| 待办事项被完成或编辑 | 事务流转为「完成」，或其字段被更新 |
| 事务符合 JQL | 被镜像为待办事项 |
| 事务在 Jira 中被解决 | 下一次轮询时完成该待办事项（周期性待办事项顺延到下一周期） |
| 事务在 Jira 中被重新打开 | 待办事项随之重新打开 |
| **两边都被修改** | **较新的修改胜出；时间相同则 Jira 胜出** |
| 在 Turbo EA 中删除待办事项 | 事务**绝不会被删除**——会添加一条注释说明已移除 |
| 在 Jira 中删除事务 | 拉取来的待办事项会被移除；由 Turbo EA 创建的待办事项则保留并在日志中标记 |

**推送近乎实时，拉取按周期进行。** 在 Turbo EA 中所做的更改数秒内即抵达 Jira；在
Jira 中所做的更改则在下一次轮询时被采集——默认五分钟以内。每一轮还会对两边做一次
对账，因此 Jira 故障或事件丢失能够自愈，而不会丢失更改。

保持一致的有四个字段：**标题**、**截止日期**、**完成状态**与**负责人**。标题对应待
办事项文本的**第一行**，因此在 Jira 中重命名事务只会替换那一行，后续的明细行保持
不变。

### 事务编号标签

已同步的待办事项会以小型链接显示其 Jira 事务编号（例如 `PROJ-123`），既出现在
[待办事项页面](../guide/tasks.md)，也出现在卡片的待办标签页中。点击即可在 Jira 中
打开该事务。此标签仅供参考——待办事项始终在 Turbo EA 中或经由同步完成。

### 签署待办事项

签署请求——等待某人批准的风险、决策或项目——属于系统待办事项，**绝不会**作为普通待
办事项推送。开启**镜像签署待办**后，它们会获得一个**单向**的 Jira 事务，直接链接到
真正进行签署的页面。

签署永远无法从 Jira 完成。若有人在义务仍未了结时关闭了镜像事务，同步会将其重新打开
并附上指回 Turbo EA 的注释。签署在 Turbo EA 中完成后，镜像会在下一次轮询时流转为
「完成」。

关闭该开关只会阻止创建*新的*镜像；已有的镜像仍会继续维护。

## 监控

**状态**行显示上次同步的时间、可能出现的错误以及本次所做工作的摘要。其下方的**最近
活动**列出最近 50 条操作，包含时间、方向（**Turbo EA → Jira**、
**Jira → Turbo EA** 或 **Sync**）、事务与详细信息。警告与错误以颜色标示——无法映射
的负责人或被拒绝的状态流转都会在这里显现。

## 权限

| 权限 | 允许 |
|---|---|
| `ext.jira-todos.admin` | 配置并运行同步——连接、项目、过滤器、手动执行与活动日志 |

没有该权限的人完全看不到这个子标签页。**终端用户无需任何额外权限**：已同步的待办
事项会直接出现在他们惯常的待办列表中，并带有事务编号标签。

## 许可证失效或扩展被停用时

同步作业及其事件处理器立即暂停，数据访问授权被撤销。**不会删除任何内容**——待办事
项保留其标签，配置也得以保留。续期许可证后，同步会从中断处继续。

API 令牌在您的实例上加密存储，并被排除在工作区迁移之外，因此绝不会离开输入它的那
个实例。

## 排查与限制

- **仅支持 Jira Cloud。** 不支持 Jira Data Center。
- **每个实例一个项目**，且事务始终以 **Task** 类型创建。
- **采用轮询而非 webhook。** Jira 侧的更改在下一次轮询时到达。Jira Cloud 的 webhook
  需要 OAuth 应用以及可从互联网访问的实例，而且仍需一次对账轮询，因此同步按设计采用
  周期方式。
- **负责人映射与邮箱隐私。** Turbo EA 先按邮箱地址匹配，匹配不到时再在项目的可指派
  用户中按显示名精确匹配。若某人在 Jira 中隐藏了邮箱*且*两套系统中的显示名不同，就
  无法完成映射；这类负责人保持原样，日志会记下未能匹配的邮箱地址。未能映射的
  Turbo EA 负责人绝不会悄悄取消 Jira 事务的指派。
- **在 Jira 中清空截止日期不会回传。** 请改在 Turbo EA 中清空。
- **签署待办事项的镜像是单向的，最多可能滞后一个轮询间隔**，因为核心的签署流程不会
  发出变更事件。
- 若已有一轮同步在进行，**立即同步**会返回 *A sync is already running*。
- 轮换实例的 `SECRET_KEY` 之后，已保存的令牌将无法解密，面板会退回
  *Not configured yet*——请重新填入令牌。
