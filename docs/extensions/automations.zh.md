# Automations

大多数企业架构治理，说到底是一张有人承诺要手工完成的清单：当一个应用的成本越过阈值却没有负责人时提出风险，
当一个组件到达生命周期终止时催促技术负责人，当一张已批准的卡片被编辑时提醒业务负责人。清单本身没有错；
落空的是执行，因为每一项都只是某人脑子里的一个提醒，而不是由平台守护的一条规则。

**Automations** 把这些承诺变成由 Turbo EA 替你执行的规则。一条规则完全由下拉选项搭建——*当*架构版图中
发生了某件事、*如果*条件成立、*那么*执行动作——而每一次运行都会作为一个变更批次记录在审计日志中，
因此一条出了错的规则，一次点击即可撤销。

## 概览

| | |
|---|---|

| **数据访问授权** | 卡片（读 + 写）、卡片与待办事件、待办（读 + 写）、用户目录、风险（读 + 写）、决策记录、通知、干系人角色 |

## 一条规则：当、如果、那么

![规则网格](../assets/img/en/86_ext_automations_rules.png)

**规则**标签页列出每条规则及其触发器、卡片类型、动作、启用开关、最近一次运行和一个播放按钮。
打开任意一条即可进入编辑器。

![规则编辑器](../assets/img/en/87_ext_automations_editor.png)

编辑器先在顶部用通俗的语言把规则复述给你，然后逐一走过它的三个部分：

**当**——什么启动一次运行。一条规则监视一种卡片类型，并在以下其中一种情况下触发：

| 触发器 | 触发时机 |
|---|---|
| 卡片被创建 / 更新 / 归档 / 恢复 | 该卡片发生变化 |
| 关系被添加 / 移除 | 一条关系（可选限定类型）触及该卡片 |
| 待办被完成 | 挂在该卡片上的一条待办被关闭 |
| 按计划 | 一条五字段 cron 表达式（UTC）到点——规则随即检查该类型的每一张卡片 |

**如果**——条件，以嵌套的**全部满足** / **任一满足**分组表示。每一行是一个从下拉选项中选出的字段、
运算符和值：卡片自身的字段和生命周期阶段、它的标签、它的干系人角色（*无人持有*、*由……持有*……）、
它的关系、应用与 IT 组件上的生命周期终止状态，以及——在*卡片被更新*时——**变化了什么**，让规则可以
只在某个值从一种状态变为另一种状态时触发。分组留空则对每一张卡片都运行。

**那么**——动作，按顺序执行。某个动作失败会终止本次运行，运行行会指出是哪一步失败。

| 动作 | 作用 | 所需授权 |
|---|---|---|
| 设置 / 清除字段、设置生命周期日期、设置子类型、父卡片、名称或描述 | 编辑卡片 | 清单写入 |
| 设置标签 | 替换、添加或移除标签，遵守单选标签组的约束 | 清单写入 |
| 创建关联卡片、建立关系 | 添加另一种类型的卡片并与之建立关系，或将两张现有卡片关联起来 | 清单写入 |
| 归档卡片 | 将其归档（30 天内可恢复） | 清单写入 |
| 指派 / 移除干系人角色 | 把某个角色授予某个人、某个角色的持有者、父卡片上该角色的持有者，或触发该规则的人 | 干系人角色 |
| 创建待办 | 在卡片上为某位受指派人创建一条带截止日期的待办 | 待办 |
| 通知人员 | 按收件人各自的偏好发送应用内 / 电子邮件通知 | 通知 |
| 提出风险、更新风险 | 在风险登记册中登记一项带类别、概率和影响的风险，关联到该卡片并指定责任人；之后的运行可以更新其标题、责任人或目标日期 | 风险 |
| 创建决策草稿 | 一份关联到该卡片的架构决策记录草稿——规则永远不会签署它 | 决策记录 |
| 调用 webhook | 向外部系统发送一个带签名的 HTTPS 请求，携带卡片、变化内容和规则 | — |
| 停止 | 结束动作列表 | — |

标题、描述和消息都是模板：`{{card.name}}`、`{{card.attributes.costTotalAnnual}}`、`{{actor.name}}`、
`{{change.old}}` 之类的变量会按卡片逐一填入，编辑器还提供一个菜单供你选择变量。

动作下方有两个选项。**每张卡片只触发一次**（默认开启）会记住规则曾为哪些内容触发过，因此一条每夜运行
的规则不会每晚提出同一项风险；当它读取的值发生变化时，它会再次触发。**夜间补查**会在每天 03:00 UTC
重新检查每一张卡片，因此错过的事件会自行补上。

## 模拟与立即运行

**模拟**以预览模式对该类型的每一张卡片运行规则——不写入任何内容——并显示有多少张卡片匹配，
以及对每张卡片而言，每个动作究竟会做什么。启用一条从未模拟过的规则时，系统会请你先模拟；
你仍然可以不模拟直接启用。

**立即运行**则动真格：它立即对每一张匹配的卡片触发，遵守*每张卡片只触发一次*，除非你勾选
*对已处理过的卡片再次触发*。结果对话框逐卡片显示做了什么，并链接到审计批次。

## 运行与审计日志

![运行标签页](../assets/img/en/89_ext_automations_runs.png)

每一次运行都是**运行**标签页上的一行：哪条规则、在哪张卡片上、如何启动（事件、计划、夜间补查、
立即运行）、如何结束，以及每一行动作。可以按规则或结果筛选；卡片自身的运行次数以标记形式显示在
其详情页上。

一次运行所做的每一次写入都会以扩展批次的形式落入**管理 → 设置 → 审计日志**，附带逐事件差异。
一次**扫描**——计划触发、夜间补查或立即运行——对它所触发的所有卡片而言是**一个批次**，因此一条
出了错的规则只需**回滚**一次，而不是每张卡片各回滚一次。回滚会撤销卡片和关系的写入，并且从
Turbo EA 2.127.0 起，还会撤销该次运行提出或编辑的风险、指派的角色、设置的标签以及创建的决策草稿。
待办和通知会被有意保留——向某人发出的请求和已送达的消息，不能靠删除来撤销——回滚预览会在应用
任何内容之前说明这一点。

## 通知会被合并

规则从不会为每张卡片各发一条通知。一次扫描会收集每个人应收到的内容，并在结束时按人、按规则只发送
**一条**通知——只涉及一张卡片时作为单独消息送达，涉及多张时则作为一份列出各卡片的摘要送达，
其标题由你在动作中设定（*摘要标题*）。逐条到来的变化——例如一次触及三百张卡片的导入——会立即
发送第一条通知，其余的则在设置中的**合并窗口**内暂存；下一分钟把累积的内容作为一份摘要发出。
每个人自己的通知偏好仍然决定走铃铛、电子邮件还是扩展渠道。

## 模板

**模板**标签页是一个现成规则的图库——没有负责人的高成本应用、180 天内到达生命周期终止、没有业务
能力的新应用、已批准却被编辑的卡片、数据质量持续一个月偏低、进入淘汰阶段的应用、带有未清关系却被
归档的卡片、转为活跃的举措、没有技术负责人的关键应用、新登记的供应商、到达生命周期终止的 IT 组件。
每一个都会以停用状态在编辑器中打开，供你调整和模拟。

## 设置

![设置](../assets/img/en/90_ext_automations_settings.png)

| 设置 | 作用 |
|---|---|
| **兜底人员** | 当规则在它所要求的角色中找不到任何人时，由此人接收待办、风险或通知 |
| **Webhook 主机允许列表** | *调用 webhook* 动作可以访问的主机，每行一个；留空则允许任何公网 HTTPS 主机。私有和内网地址始终被拒绝 |
| **每次计划运行检查的卡片数** | 一次计划扫描在停下并把余下卡片留给下一次之前查看多少张卡片 |
| **合并在此时间内到达的通知** | 合并窗口，以分钟计；0 表示每条通知都在下一分钟发出 |

## 演示数据

设置中的**载入演示数据**会在示例架构版图上安装模板和三条演示规则，启用其中大多数并让少数几条各运行
一次，让规则、运行和审计日志标签页有内容可看。**移除**会把这些原样收回——规则、运行记录，以及它们
创建的待办和风险。

## 如果许可到期或扩展被停用

该页面会从菜单中消失，计划停止执行，事件不再被分发。不会删除任何内容：规则、其运行记录以及它们
写入的一切——卡片、风险、待办、决策——都原样保留。续期许可或重新启用扩展后，规则会回来，且仍处于
启用状态。

## 说明与限制

- Turbo EA 允许一个扩展每分钟执行 60 个带审计的批次。对一份非常大的清单进行扫描时，会在达到上限后
  暂停并在下一个周期继续；立即运行会在结果中说明这一点，下一次扫描会接着处理余下的卡片。
- 监视*卡片被更新*的规则只能看到它启用之后发生的变化；对于既有的架构版图，请使用立即运行或等待
  夜间补查。基于**变化了什么**的条件只匹配实时更新。
- Webhook 仅支持 HTTPS，使用每个实例专属的密钥签名，从不跟随重定向，并在 10 秒后超时；响应会记录
  在运行记录上。
- 规则只能更新它自己提出的风险，而且永远不能签署决策、转换风险状态或完成待办——这些仍然是人的行为。
