# Политика совместимости

Начиная с версии `1.0.0`, Turbo EA гарантирует документированную обратную совместимость в рамках одной основной ветки версий. Эта страница — договорённость: в ней описано, что остаётся стабильным, что может измениться и как работает устаревание, чтобы операторы могли планировать обновления без неожиданностей.

Политика действует для `1.x`. В будущей ветке `2.x` она может быть пересмотрена; в таком случае вместе с примечаниями к выпуску `2.0.0` будет опубликовано руководство по миграции.

---

## Что охватывается

### Схема базы данных (миграции Alembic)

В рамках `1.x`:

- Миграции являются **аддитивными** или **обратно совместимыми при обновлении**.
- Новые столбцы можно добавлять в любое время.
- Существующие столбцы не удаляются без цикла устаревания.
- Существующие столбцы не переименовываются без цикла устаревания (переименование выполняется по этапам add-new-column → backfill → deprecate-old-column → drop-in-next-major).
- Типы можно только расширять (например, `varchar(80)` → `varchar(255)`); сужение проходит через устаревание.
- Ограничения внешних ключей не становятся строже без цикла устаревания (например, `ON DELETE SET NULL` не превращается в `ON DELETE CASCADE`).

Операторы могут уверенно обновлять систему: автоматическую миграцию при запуске backend безопасно выполнять на производственных данных.

### Встроенная метамодель

В рамках `1.x` метамодель из `backend/app/services/seed.py` стабильна:

- Ключи встроенных типов карточек (`Application`, `Initiative`, `BusinessCapability` и т. д.) не переименовываются и не удаляются.
- Ключи встроенных полей этих типов не удаляются без цикла устаревания.
- Ключи встроенных типов связей не переименовываются и не удаляются без цикла устаревания.
- Стандартные подтипы, поставляемые со встроенными типами, стабильны.

Собственные настройки операторов (пользовательские типы карточек, поля, добавленные через интерфейс администратора, пользовательские типы связей) принадлежат оператору и не охватываются этой политикой.

### REST API (`/api/v1/`)

В рамках `1.x`:

- Конечные точки в `/api/v1/` не удаляются без цикла устаревания.
- Имена существующих полей запросов и ответов не переименовываются без цикла устаревания.
- Типы полей не меняются несовместимым образом (например, строка → массив).
- Новые необязательные поля запросов и новые поля ответов не нарушают совместимость и могут появиться в любом минорном выпуске.
- Новые конечные точки не нарушают совместимость и могут появиться в любом минорном выпуске.
- Семантика аутентификации (JWT `Bearer`, структура полезной нагрузки `/auth/login`) стабильна.
- Семантика кодов состояния HTTP стабильна для документированных путей успеха и ошибок.

Поведение за пределами документированной поверхности (недокументированные заголовки, текст внутренних сообщений об ошибках, порядок без указанного `sort_by`) не охватывается.

### Ключи разрешений

Ключи разрешений, определённые в `backend/app/core/permissions.py`, стабильны в рамках `1.x`. Новые ключи добавлять можно; существующие не переименовываются и не удаляются без цикла устаревания.

Набор разрешений, предоставляемых **по умолчанию** начальным ролям (`admin`, `bpm_admin`, `member`, `viewer`), может меняться между минорными выпусками с соответствующим упоминанием в CHANGELOG. Операторы, настроившие разрешения ролей в своём развёртывании, не затрагиваются.

### Конфигурация (переменные среды)

Существующие переменные среды, описанные в `CLAUDE.md` и `README.md`, стабильны в рамках `1.x`. Можно добавлять новые переменные с разумными значениями по умолчанию. Значения по умолчанию могут изменяться с упоминанием в CHANGELOG, если это важно для операторов (например, новый порт по умолчанию).

### Зашифрованные при хранении секреты

Маркер префикса `enc:` и ключ, производный от Fernet, в `backend/app/core/encryption.py` стабильны в рамках `1.x`. Операторам не нужно повторно шифровать секреты при минорных обновлениях.

## Цикл устаревания

Если требуется удалить то, что охватывается этой политикой:

1. **Пометить как устаревшее в минорном выпуске N.** Запись CHANGELOG содержит раздел `Deprecated` с описанием изменения. Для конечных точек API устаревший маршрут отправляет заголовок ответа `Deprecation: true` (RFC 8594) и заголовок `Sunset` с указанием самой ранней предполагаемой даты удаления.
2. **Продолжать поддержку в минорном выпуске N+1.** Удаление не может состояться в том же минорном выпуске, где объявлено устаревание. Устаревшая форма продолжает работать.
3. **Самое раннее удаление — в минорном выпуске `N+2` или в `2.0`** (в зависимости от того, что наступит раньше). При удалении в CHANGELOG добавляется раздел `Removed` и примечание о миграции.

Для изменений структуры данных (миграций Alembic) действует тот же ритм `N` → `N+1`, выраженный последовательностью add-new → backfill → drop-old.

## Что не охватывается

Следующие элементы явно находятся вне области действия и могут измениться в любое время:

- **Внутренняя структура модулей Python** в `backend/app/`. Импорт `app.models`, `app.services` и т. п. не является частью публичного API. Плагинам и скриптам, зависящим от внутренних импортов, следует зафиксировать конкретную версию Turbo EA.
- **Структура блоков JSONB**, хранящихся во встроенных таблицах (`fields_schema`, `section_config`, `attributes`, `lifecycle`), за исключением данных, читаемых документированным REST API. Структура JSON на диске может меняться для поддержки новых функций.
- **Внутреннее устройство frontend**: пути к файлам компонентов, сигнатуры props компонентов в `frontend/src/`, содержимое `frontend/src/types/index.ts` и оформление компонентов MUI. Пользователи входящего в комплект frontend защищены от этих изменений; ответственность за встраивание компонентов из дерева исходного кода лежит на встраивающей стороне.
- **Настройки метамодели, добавленные оператором.** Если вы добавили пользовательский тип карточки или поле через интерфейс администратора, при изменении вы отвечаете за миграцию.
- **Демонстрационные и начальные данные** (`SEED_DEMO=true`). Демонстрационный набор данных может свободно меняться между выпусками.
- **Поставляемые сторонние сервисы**: версия DrawIO, образ Ollama в комплекте, версия встроенного swagger-ui-dist. Они могут обновляться в любое время.
- **Поведение при нестандартной конфигурации**, прямо обозначенной как экспериментальная в записях CHANGELOG.

## Что на самом деле меняет «1.0.0»

По сравнению с серией `0.x`, сама версия `1.0.0` не добавляет функции: с неё начинают действовать перечисленные выше обязательства. Код в `1.0.0` совпадает с кодом из `0.71.0`, дополненным усилением безопасности цепочки поставок и изменениями процесса участия, описанными в [записи CHANGELOG для `1.0.0`](https://github.com/vincentmakes/turbo-ea/blob/main/CHANGELOG.md#100---2026-05-05).

Выпуски до `1.0` не охватывались этой политикой. Миграции между версиями `0.x` могли включать и действительно включали удаление и переименование элементов схемы, а также несовместимые изменения метамодели. Начиная с `1.0.0`, такие изменения проходят цикл устаревания.
