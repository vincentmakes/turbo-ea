# 兼容性政策

从 `1.0.0` 版本起，Turbo EA 承诺在同一主版本系列内提供有文档说明的向后兼容性。本页是这项承诺的约定：说明哪些内容保持稳定、哪些内容可能变化，以及弃用流程如何运作，帮助运营人员安心规划升级。

本政策适用于 `1.x`。未来的 `2.x` 系列可能会修订本政策；如有修订，`2.0.0` 发行说明将附带迁移指南。

---

## 覆盖范围

### 数据库架构（Alembic 迁移）

在 `1.x` 中：

- 迁移是**增量式**的，或在升级时**向后兼容**。
- 可随时添加新列。
- 删除现有列前必须经过弃用周期。
- 重命名现有列前必须经过弃用周期（重命名按以下步骤实施：add-new-column → backfill → deprecate-old-column → drop-in-next-major）。
- 类型更改仅限于扩大范围（例如 `varchar(80)` → `varchar(255)`）；缩小范围的更改须经过弃用流程。
- 外键约束不会在未经弃用周期的情况下变得更严格（例如，`ON DELETE SET NULL` 不会改为 `ON DELETE CASCADE`）。

运营人员可以放心升级；后端启动时自动执行的迁移可安全用于生产数据。

### 内置元模型

在 `1.x` 中，`backend/app/services/seed.py` 提供的元模型保持稳定：

- 内置卡片类型键（`Application`、`Initiative`、`BusinessCapability` 等）不会重命名或删除。
- 这些类型的内置字段键不会在未经弃用周期的情况下删除。
- 内置关系类型键不会在未经弃用周期的情况下重命名或删除。
- 内置类型附带的默认子类型保持稳定。

运营人员自己的定制内容（自定义卡片类型、通过管理界面添加的字段、自定义关系类型）由运营人员负责，不在本政策范围内。

### REST API (`/api/v1/`)

在 `1.x` 中：

- `/api/v1/` 下的端点不会在未经弃用周期的情况下删除。
- 现有请求和响应字段名称不会在未经弃用周期的情况下重命名。
- 字段类型不会发生不兼容变化（例如从字符串变为数组）。
- 新增的可选请求字段和响应字段均不构成破坏性更改，可在任何次版本中加入。
- 新增端点不构成破坏性更改，可在任何次版本中加入。
- 身份验证语义（`Bearer` JWT、`/auth/login` 的载荷结构）保持稳定。
- 对于文档记录的成功和错误路径，HTTP 状态码语义保持稳定。

超出文档所述范围的行为（未记录的标头、内部错误消息文本、未指定 `sort_by` 时的排序）不在覆盖范围内。

### 权限键

`backend/app/core/permissions.py` 中定义的权限键在 `1.x` 中保持稳定。可以添加新键；现有键不会在未经弃用周期的情况下重命名或删除。

授予种子角色（`admin`、`bpm_admin`、`member`、`viewer`）的**默认**权限集合可能在次版本之间发生变化，并会在 CHANGELOG 中说明。自行定制部署中角色权限的运营人员不受影响。

### 配置（环境变量）

`CLAUDE.md` 和 `README.md` 中记录的现有环境变量在 `1.x` 中保持稳定。可以使用合理的默认值添加新变量。如果默认值的变化与运营人员相关（例如新增默认端口），CHANGELOG 会予以说明。

### 静态加密的机密

`backend/app/core/encryption.py` 中的 `enc:` 前缀标记和 Fernet 派生密钥在 `1.x` 中保持稳定。运营人员在次版本升级之间无需重新加密机密。

---

## 弃用周期

如果需要删除本政策覆盖的内容：

1. **在次版本 N 中标记为弃用。** CHANGELOG 条目包含 `Deprecated` 部分，说明该更改。对于 API 端点，弃用路由会发送响应标头 `Deprecation: true`（RFC 8594）以及 `Sunset` 标头，指出最早计划移除的时间。
2. **在次版本 N+1 中继续支持。** 不得在标记弃用的同一个次版本中移除。已弃用的形式仍可正常工作。
3. **最早在次版本 `N+2` 或 `2.0` 中移除**（以先到者为准）。移除时会在 CHANGELOG 中添加 `Removed` 部分，并提供迁移说明。

对于数据形状更改（Alembic 迁移），采用相同的 `N` → `N+1` 节奏，即 add-new → backfill → drop-old。

---

## 不在覆盖范围内的内容

以下内容明确不在范围内，可能随时变化：

- `backend/app/` 下的**内部 Python 模块布局**。导入 `app.models`、`app.services` 等不属于公共 API。依赖内部导入的插件或脚本应固定使用特定的 Turbo EA 版本。
- 内置表中存储的 **JSONB 数据块结构**（`fields_schema`、`section_config`、`attributes`、`lifecycle`），但文档化 REST API 读取的内容除外。磁盘上的 JSON 形状可能随新功能演进。
- **前端内部实现**：组件文件路径、`frontend/src/` 中组件的 prop 签名、`frontend/src/types/index.ts` 的内容以及 MUI 组件样式。使用随附前端的运营人员不会受到影响；从源代码树嵌入组件的使用者需自行承担相关责任。
- **运营人员引入的元模型定制**。如果通过管理界面添加自定义卡片类型或字段，修改时的迁移由您负责。
- **演示和种子数据**（`SEED_DEMO=true`）。演示数据集可以在各版本之间自由演进。
- **捆绑的第三方服务**：DrawIO 版本、捆绑的 Ollama 镜像、嵌入式 swagger-ui-dist 版本。它们可能随时升级。
- CHANGELOG 条目明确标记为实验性的**非默认配置行为**。

## “1.0.0”实际带来的变化

与 `0.x` 系列相比，`1.0.0` 本身不是功能版本，而是上述承诺开始生效的节点。`1.0.0` 发布的代码与 `0.71.0` 发布的代码相同，另加供应链加固和贡献流程变更；详情请参阅 [`1.0.0` CHANGELOG 条目](https://github.com/vincentmakes/turbo-ea/blob/main/CHANGELOG.md#100---2026-05-05)。

`1.0` 之前的版本不受本政策覆盖。`0.x` 版本之间的迁移曾经可以且确实包含架构删除、重命名和破坏性元模型更改。从 `1.0.0` 起，这类更改必须经过弃用周期。
