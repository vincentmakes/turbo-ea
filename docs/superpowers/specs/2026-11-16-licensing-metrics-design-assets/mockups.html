Workspace transfer. What a bundle holds and what happens when an older bundle is imported.

New bundle, sheet order

  1. LicenseMetrics key, label, sort_order, archived, translations
  2. LicenseTypes the same plus metric_key, natural key (metric_key, key)
  3. CardLicenses unchanged: items keyed by metric key and type key, no ids

Card types no longer carry licensingModel. The format version does not change.

Older bundle (no LicenseMetrics, no metric_key)

  • Default metrics Users and Installations are created if the target lacks them.
  • Each type goes to the metric(s) under which the bundle's own CardLicenses has data for it; used under both, it is duplicated; no data, attached to both.
  • Derived rows never change archived or sort_order of a row the target already has.
  • licensingModel is removed from the card types and from the card attributes; never re-added.
  • A cell whose metric or type exists in neither bundle nor target is skipped and reported.

Target already has a catalogue

  • Rows are matched by natural key. The same type key under another metric is a different row.
  • A new-format bundle into an older instance is not refused; the older instance ignores the sheets it does not know.
