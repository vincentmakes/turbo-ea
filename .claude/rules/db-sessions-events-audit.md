# Database sessions, card events / `updated_at`, and the Security & admin log

> Loaded when you touch `backend/app/database.py`, `backend/app/api/deps.py`, `backend/app/api/v1/events.py`, `backend/app/services/event_bus.py`, … (full list in the frontmatter). Moved verbatim from `CLAUDE.md`; edit it here.

- **Never hold a database session across work that is not database work.** A session checks a connection out of the pool on its **first `execute()`** and keeps it — inside an open transaction — until it commits or closes. The pool is small: `DB_POOL_SIZE + DB_MAX_OVERFLOW` (**30 by default**, `backend/app/config.py`) on a **single** uvicorn process (`Dockerfile` passes no `--workers`). This has shipped as a bug twice, so it is a rule, not a preference:
  - **A streaming endpoint must not take `Depends(get_db)`.** `get_db` is a yield-dependency — FastAPI unwinds it only when the *response completes*, and an SSE / `StreamingResponse` response completes when the client disconnects, i.e. when the browser tab closes. Querying that session left its connection checked out, `idle in transaction`, for the tab's whole lifetime, so **every open tab permanently consumed one of the 30** ([#901](https://github.com/vincentmakes/turbo-ea/discussions/901), fixed in 2.38.0). Do the auth and lookup work in an explicit `async with async_session()` block that closes **before** the response object is constructed, and keep the generator body free of database access. See `event_stream` (`backend/app/api/v1/events.py`) and its guard tests in `backend/tests/api/test_events.py`.
  - **A background job must not hold its session across slow non-DB work** — LLM round-trips, outbound HTTP, file parsing. The shape is `read → commit() → slow work → fresh short session for the writes`, not one session wrapping the whole job. These transactions *write*, so unlike the streaming case they also hold back the vacuum horizon for as long as they run. Where a phase must stay atomic (`apply_bundle`, `apply_migration`, a delete-and-rebuild), move only the pre-write parse out and leave the atomic phase in one transaction. Guard tests: `backend/tests/services/test_db_session_holding.py`.
  - **A helper must never commit or roll back a session it was handed** — it cannot know what the caller has pending, so committing persists half-finished work and rolling back silently discards it. If a helper needs its own read, it opens its own short session: `call_ai` (`backend/app/services/turbolens_ai.py`) is the canonical example.
  - **Do not assume 30 connections are available.** Operators shrink the pool via `DB_POOL_SIZE` / `DB_MAX_OVERFLOW` / `DB_POOL_TIMEOUT` to fit a managed PostgreSQL whose plan caps the database (see `docs/admin/operations.md`).

- **A Security & admin log entry is written for a person to read: `details` has four keys, and its values are labels, not keys.** `audit_log.record` takes `reason` (a short snake_case failure code, auth/SSO/proxy/password only), `changes` (`{field: {"old", "new"}}`, snake_case field names), `items` (semantic changes `{"kind": "<noun>.<verb>", ...args}`) and `context` (plain facts that are not a change), and `validate_details` refuses anything else — another top-level key, a nested value, an item whose `kind` is not in `AUDIT_ITEM_KINDS` — with a `ValueError`, so a writer cannot drift back to dumping a payload. Every value is a scalar or a flat list of scalars, and anything an admin defined (a role, card type, field, section, option, subtype, tag, extension, portal) is named by its **label**: the drawer renders what it is given and has no metamodel to resolve a key against. System enumerations stay as codes and are labelled through `securityLog.values.*`; ISO datetimes, booleans, colours, sizes, permission keys and locale codes are formatted by the frontend; secrets stay `***`. A structural change (a card type's `fields_schema`, layout, translations, keyed lists, permission matrices, portal filters) is never logged as a count or a fingerprint: it goes through the pure builders in `services/audit_changes.py` (`item()` refuses an unknown kind) and renders through one `securityLog.changes.<noun>_<verb>` sentence template per kind (`frontend/src/features/admin/securityLogDetails.ts` + `SecurityLogEntryDrawer.tsx`). A new kind is a three-place change — `AUDIT_ITEM_KINDS`, the templates in all 10 locales, and the vocabulary — and rows written before the contract keep rendering through the drawer's legacy fallback. Guard tests: `backend/tests/services/test_audit_log_guard.py` (the details scan), `frontend/src/features/admin/securityLogChanges.test.ts` (every kind a writer passes is declared and has a template in every locale).

- **A write path that can move `cards.updated_at` must also persist a card event.** The inventory's **Modified** column (`meta_updated_at`, `InventoryPage.tsx`) and a card's **History** tab (`GET /cards/{id}/history`) are two renderings of the same fact, and users filter that column by date to find cards nobody has reviewed — so a card that says "changed yesterday" and shows an empty history is a card nobody can triage. `updated_at` comes from `TimestampMixin.onupdate=func.now()` (`backend/app/models/base.py`), which fires on **any** UPDATE of the row; the History tab reads `Event` rows, which exist only when `event_bus.publish` is called **with `db=`** (without it the event is SSE-only and vanishes). Every write path therefore owes exactly one of two things:
  - **It changed content** → `await event_bus.publish("<type>", {...}, db=db, card_id=card.id, user_id=...)`. Publishing without `db=` does not count. A `changes` payload must be `{field: {"old": …, "new": …}}`, with `attributes` and `lifecycle` carrying the **whole** old/new dict — that is the only shape `parseChanges` (`frontend/src/features/cards/sections/HistoryTab.tsx`) renders, and anything else is dropped silently, with no error anywhere.
  - **It is pure derived-value maintenance** — a data-quality rescore, a bulk calculated-field re-run, a hierarchy-level or card-reference backfill, with no per-card user intent — → run it inside `derived_maintenance(db)` (`backend/app/services/derived_writes.py`), which pins `updated_at` to its stored value so the column keeps meaning "content last changed". Emitting an event per card instead is not the answer: one field-weight change rescores *every* card of the type.
  
  A same-value assignment is already free — SQLAlchemy compares by equality and drops the column from the UPDATE — so the bug is never "I re-assigned an unchanged value"; it is a genuine write nobody recorded, or `flag_modified` forcing a write that did not happen. What this codifies: an Excel import that only synced **tags** (`POST /cards/{id}/tags` published nothing while rescoring `data_quality`), a platform-migration apply (zero `event_bus` references under `services/migration/`, plus an unconditional `updated_by`), a ServiceNow pull (published, but without `db=`), a bulk edit re-dating the cards it left alone, and an admin moving one field weight each re-dated cards whose history was empty ([#995](https://github.com/vincentmakes/turbo-ea/discussions/995), fixed in 2.87.0). Guard tests: `backend/tests/services/test_updated_at_invariant.py`.
