# AG Grid pages: column freeze, drag-fill and filter sidebars

> Loaded when you touch `frontend/src/components/grid/**`, `frontend/src/components/FilterSidebar*`, `frontend/src/features/inventory/**`, `frontend/src/**/*Grid*.tsx`, … (full list in the frontmatter). Moved verbatim from `CLAUDE.md`; edit it here.

- **Every AG Grid must offer column freeze, through the shared hook.** Pinning a column to the leading edge so it stays readable while scrolling sideways is a per-user preference on *every* grid, not a per-page feature. AG Grid Community renders `colDef.pinned` but ships no UI to set it (the column menu's Pin submenu is Enterprise), so the affordance lives in `useColumnFreeze` (`frontend/src/components/grid/useColumnFreeze.ts`): it hands the **stock** header component a custom `template` carrying two extra pins and installs a capture-phase click delegate on the grid wrapper that calls `setColumnsPinned`. Wire a new grid with `headerComponentParams: columnFreeze.headerComponentParams` on `defaultColDef`, `ref={columnFreeze.containerRef}` + `...columnFreeze.sx` on the wrapper, and — on any grid with row selection — `selectionColumnDef={columnFreeze.selectionColumnDef}`, which pins the checkbox column so a frozen column can never render to its left (AG Grid draws the whole pinned region ahead of everything unpinned, and the selection column's own `lockPosition: "left"` only orders it *within* its region). Do **not** write a custom `headerComponent` for this — replacing the header loses sorting, the sort indicator, the filter button and its active state; the template approach keeps all of it. Persistence is always the same shape: the page keeps the frozen colIds as **their own pref**, passes `frozen` + `onFrozenChange`, and maps the column defs through `applyFrozen()`. Do **not** carry a freeze inside a `getColumnState()` snapshot even on a page that persists one (Inventory does) — that snapshot's restore stops re-applying as soon as the user drags or resizes a column, so a freeze made after that is saved but never restored; strip `pinned` from the restored state so the snapshot and `applyFrozen` cannot fight. A page whose column chooser is a *sibling* of the grid (ADR) keeps the pref one level up, next to its `hiddenColumns`. A column that a page wants permanently frozen belongs in that page's default `frozenColumns`, never in a hard-coded `pinned: "left"` colDef, or the user can't release it.
- **Drag-fill in grid edit mode goes through `useDragFill`, and never through a bulk endpoint.** Filling one cell's value down a column is the Excel gesture users expect once cells are editable. AG Grid ships it as `enableFillHandle`, which is Enterprise, so it is re-implemented in `useDragFill` (`frontend/src/components/grid/useDragFill.tsx`) + the pure helpers in `dragFill.ts`, and confirmed through `DragFillConfirmDialog` before anything is written. Unlike column freeze/reorder this is **edit-mode**-scoped rather than grid-scoped — a grid with no editable cells shows no handle, so `InventoryPage` is the only core wiring; extension grids reach the hook through `loadAgGrid` (UI SDK 1.30) and own the same invariants. Five invariants: **(1)** the fill is **write-then-reload** — it persists row by row through the page's own per-cell primitive (`persistCellValue`) and calls `loadData()` **once** at the end; it must never call `node.setDataValue()`, which would re-fire `onCellValueChanged` and write every row twice, and it never runs a `valueSetter`, which is what keeps it clear of the in-place-mutation stale-value trap documented at the top of `InventoryPage.tsx`. **(2)** **Never `PATCH /cards/bulk` for an attribute fill.** `bulk_update` (`backend/app/api/v1/cards.py`) applies one `updates` payload to every id and replaces `attributes` wholesale per card, so a bulk fill of one key would wipe every other attribute on every target; per-card `PATCH /cards/{id}` merging onto that card's own `attributes` is the only correct path (guard test: `InventoryDragFill.test.tsx`). **(3)** For a diff-persisted column (tags, stakeholders) the old value passed per row is the **target's own** value, not the source's — the semantic is "make this row's set equal the source's", and `currentFieldValue` is what supplies it. **(4)** The value is deep-copied per row (`cloneFillValue`) so two filled rows can never share an array identity. **(5)** One wrapper ref, minted by `useColumnFreeze` and borrowed here; a hook must not claim a `gridProps` key another hook owns (`useRowGrouping` owns `onModelUpdated`), so `useDragFill` returns `onCellFocused` alone and takes the rest through `api.addEventListener`. Name is deliberately not fillable — duplicate names fail the backend's sibling-name uniqueness on every hierarchical type. See `frontend/UI_GUIDELINES.md` §3.6.
- **Grid filter sidebars must match the Inventory sidebar, visually as well as structurally.** Any AG Grid page with a left-hand filter panel (`InventoryFilterSidebar` is the reference; `AuditLogFilterSidebar`, `RiskFilterSidebar`, `ResourcesFilterSidebar` follow it) uses the same anatomy: collapsed 44px rail with an active-filter count chip, tabbed **Filters / Columns** header with a change dot, collapsible sections, drag resize handle, and `turboea.<page>.prefs` localStorage persistence through a validating loader. Two rules are routinely forgotten and are what make a new sidebar look "not quite right": **(1) every section header takes an `icon` and a `count`** — never a bare label; **(2) option rows carry the entity's own visual identity** — a card type renders its metamodel icon in its metamodel colour (via `useTypeLabel()` for the label), an icon-bearing entity renders its icon, a colour-only option renders a 10px round dot, and a mutually-exclusive state (approval / lifecycle / archived / severity) renders as filled-vs-outlined coloured `Chip`s rather than checkboxes. The Columns tab additionally needs a per-column glyph, an italic indeterminate **Select all** row, a selected-count caption with a `restart_alt` **Reset**, locked columns rendered checked + disabled inside a `Tooltip`, and a **freeze pin on every row** (`ColumnFreezeToggle`, driven by the page's `columnFreeze.frozenColumns` / `toggleFrozen`) rendered as a *sibling* of the row button — a child of a locked (disabled) row would never receive its click. Full spec: `frontend/UI_GUIDELINES.md` § 3.11.
