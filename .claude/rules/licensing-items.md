# Licensing items: licenses of an Application / IT Component are a yearly standard object

> Loaded when you touch the licensing services, routes, models, migrations 177/178/179/192, the license catalogue dialog, the Licensing section or the Licensing report (full list in the frontmatter). Fork-only file: upstream never edits it.

- **Licenses live in `card_licenses`, one row per `(card_id, fiscal_year)`, `items` JSONB `{metric_key: {type_key: {licensed, actual}}}`. Metrics and types are catalogue data, never constants.** `license_metrics` (stable `key`, label + flat `{locale: str}` translations, `archived`, `sort_order`) and `license_types` (the same plus `metric_key`, unique on `(metric_key, key)`, so "Prod" may exist under two metrics; a type never moves to another metric). Both are archived, never deleted, and a key is never renamed. Read the catalogue once per request with `license_catalogue.load_catalogue` (`LicenseCatalogue`: `metric()`, `type(metric, key)`, catalogue order) and pass it down; never re-query it per cell. Row lookup, the year window and the lock go through `services/yearly_rows.py`, shared with `card_costs`: never re-implement them. The only constant left is the set of card types that hold licenses, `LICENSE_TYPES` (backend, `frontend/src/lib/licenses.ts`).
- **The pairs `metric:type` of a card are derived from each year's cells; nothing else lists them.** A pair exists in a year when that year's row has its cell; a pair added without values is `{licensed: 0, actual: null}`; removing a pair clears that year's cell only. There is no per-card field of tracked metrics: `licensingModel` is gone (migration 192), never re-add it or a substitute. A pair is written `metric:type` everywhere it is one string (`pairKey` / `parsePairKey` in `lib/licenses.ts`, the report's `license_type` parameter, the event payload, the import preview), and labelled `Metric: Type` with both parts resolved from their own translations (`pairLabel`, `useFieldLabel`), never the key as fallback.
- **Year resolution is the cost one, with a licensed-only carry.** A year with a row (even empty) is confirmed; only the CURRENT year with no row falls back to the latest earlier row, `confirmed=false`, and carries `licensed` only, never `actual`; the pairs shown follow the carried cells. The Forecast and past years never fall back. The Forecast row stores `licensed` only (an `actual` is refused). `actual` absent/`null` is "no data", different from `0`; `licensed` absent counts as 0. Section window `current-4 … current+1`, writes `current-5 … current+1`.
- **A status is decided in exactly one place, `services/license_status.py`.** Per license type, no compensation between types and never across metrics: `over` when actual > licensed, `approaching` at >= 80 % and not over; card priority `over` > `approaching` > `no_actual_data` > `compliant`; **a card with no pair in the year is `no_actual_data`** (`card_status([])`); a card's worst bar is `card_worst`; totals are per metric, informational, and never drive a status; the Forecast year has no status. The report, the card section, the table and the tiles all call it, and the frontend only formats what the server returns: never recompute a status in TSX.
- **Writes go through `merge_cell` (`card_licenses.py`), the one write rule, for the section, the dialogs and the import alike.** An unknown metric is `invalid_metric`, a type not of that metric `unknown_type`; a NEW cell in an archived metric or type is refused (`archived_metric` / `archived_type`, 409), an existing one keeps counting and can be edited; `copy_to_forecast` passes `allow_archived=True`. An empty import cell leaves the stored value alone; `PUT` with `actual: null` clears it. Writes lock the year row (`FOR UPDATE`); `apply_write` loads the catalogue once and hands it to the op; the service never commits.
- **The catalogue routes are scoped by metric and share `item_catalogue`.** `GET /metamodel/license-metrics` returns every metric with its types nested (archived included) and is open to any signed-in user; `POST /metamodel/license-metrics`, `PATCH /metamodel/license-metrics/{key}`, `POST /metamodel/license-metrics/{metric_key}/types` and `PATCH /metamodel/license-metrics/{metric_key}/types/{key}` need `admin.metamodel` (404 for an unknown metric, 409 `duplicate_key`, 422 otherwise; an update body refuses `key` / `metric_key`). A per-metric catalogue goes through `item_catalogue`'s `scope=` (`license_types._scope`), never a hand-written lookup. Audit targets name both parts (`license_type`, `metric/key`, `Metric / Type`). The frontend reads the catalogue only through `useLicenseCatalogue` (inflight-promise singleton); every catalogue write calls `invalidateLicenseCatalogue()`. The admin dialog is `ManageLicenseTypesDialog` (metrics, each with its types), reusing `CostItemEditDialog` for create/edit.
- **Permissions are exactly the costs ones.** View = `licenses.view` OR any stakeholder on the card; edit = `licenses.edit` OR a stakeholder role with `card.edit` on THAT card; a hidden card is 404 (`CardReadScope`). `licenses.edit` is admin only by default; the report needs `licenses.view` (`ROUTE_PERMISSIONS`), the import the global `licenses.edit`.
- **Events carry keys only and every feed redacts them.** `card.licenses_updated` carries the year's `metric:type` pair keys under `changes.license_types` (and `fiscal_year`), never counts; it is not rollbackable (`rollback_service.py`). `audit_labels.license_type_labels` reads a pair key as `Metric / Type` and an old event's plain type key as the type's label. Legacy `card.updated` diffs of the four old extension keys are redacted too. Every event feed goes through `redact_cost_events` (`cost_event_redaction.py`): add any new feed there, never a second redactor.
- **Migrations 177 (tables, permissions) and 178 (move the extension's data) leave the extension installed; 179 put `licensingModel` in a `Licensing` section; 192 replaced it with the metric catalogue.** 178 moves the four `ext.licensing.multivalue` values into the current fiscal year's row, turns each distinct category into a catalogue entry, strips the extension keys and fields (`strip_ext_fields`), copies `ext.licensing.view/manage` grants to `licenses.view/edit` and writes `licensing_migration_report`. 192 creates `license_metrics` (`users`, `installations`), adds `license_types.metric_key` and places each type by `derive_type_metrics` (data under one metric: there; under both: duplicated with the same label, translations and archived flag; none: under both), strips `licensingModel` and the then-empty `Licensing` section (`without_model_field`) and clears the stored values without moving `cards.updated_at`, keeps `card_licenses.items` untouched (data of a metric a card did not track now shows), and writes `license_metrics_migration_report` (lists capped at 200, key-scoped write). Its downgrade refuses while a type key exists under two metrics. The data-quality rescore marker is bumped in `app/main.py` (`dataQualityCanonicalRescoreDoneV5`), not by the migration. **The helpers 178/179 import (`move_model_field`, `LICENSING_MODEL_FIELD`, `licensing_section`, `LICENSING_SECTION`) and 192's `licensing_migration.DEFAULT_METRICS` are frozen**: the app reads the live `license_types.DEFAULT_METRICS`, which `seed.py` uses through `seed_default_metrics` (insert-only, no types) because a fresh install runs no migration; `test_no_app_module_takes_the_default_metrics_from_the_migration_helpers` keeps the frozen copy out of the app.
- **The report is built from the cost report blocks, imported, never rebuilt:** `ReportShell`, `CardScopeFilter`/`useCardScope`, the fiscal-year Time Travel row (`FiscalYearTimeTravel`), `useApiQuery`, `EChart`, `CardDetailSidePanel`, `CardPicker`, the drill helpers and `costColors` (a type's hue is `catalogueHues` by `sort_order` inside its metric, archived included; 9th and later fold into grey). `GET /reports/licensing` takes `card_types` (Application, IT Component or both), optional `metric` and `license_type` (`metric:type`; a bare type key is refused), `fiscal_year`, `group_by`, `card_id`, and returns one row per card (`by_metric`, `status`, `worst_pct`, `confirmed`, alias and logo) plus `metrics_in_year` / `types_in_year` for the selects; there is no trend. Rows: with no selection every card of the scope that counts in the year (`is_live_in_fiscal_year` for the current year, a stored row for any other), a card without pairs included as `no_actual_data`; with a metric or type selected only the cards holding a cell of it. A Platform `card_id` aggregates direct `relPlatformToApp`/`relPlatformToITC` links, each card once, rows without status and no tiles. Two views: Utilisation (one collapsible `LicensingCardRow` per card, expanded it shows the card's `PairBars`) and Table (`LicensingTable`, a column group per pair, per-metric totals). The status tiles count rows; clicking one filters to it. History (`PairHistory`) shows only when a row is expanded and a pair picked.
- **The card section and the report share `components/licensing/`.** `PairBars` draws one horizontal bar per pair, grouped by metric, Licensed wide and pale behind Actual narrow and solid, the consumption at the end, plus a button per pair (a chart is not keyboard-reachable); `PairHistory` draws one pair over the section's years, Forecast included; `licensePairs.ts` builds names, hues, groups and history rows; the option builders are pure (`pairBarsOption.ts`, `pairHistoryOption.ts`) and the bar tooltip is appended to `body` so it is never clipped. Never draw counts of two metrics on one axis. **The fiscal year is chosen with `FiscalYearTimeTravel`** in the report (the cost report's years without the Forecast) and the section (the six years of `data.years`); it renders nothing under two years and is hidden in print. **Add** offers a metric, then that metric's types, from `addableCatalogue` (active metrics and types, the year's held pairs left out: adding a held pair would overwrite its cell), and writes the selected year.
- **The import (`license_import.py`, `POST /licenses/import?dry_run=`) is validate-then-apply on the same bytes.** The file is checked by its bytes (`uploads.md`, 20 MB cap, zip-bomb guard through `_check_declared_sizes`); columns `Component | Metric | License type | Year | Licensed | Actual`; cards matched by exact case-insensitive name among readable, non-archived Application/IT Component cards (duplicate name = skipped `ambiguous_card`); the metric by key, then the legacy `user(s)` / `installation(s)` spellings (`METRIC_ALIASES`, reaching only metrics keyed `users` / `installations`), then a unique English label (`invalid_metric`, `ambiguous_metric`); the type by key or label among that metric's types only (`unknown_license_type`, `ambiguous_license_type`, `type_not_in_metric` when it exists under another metric); duplicate cells, bad years, non-integers, an empty row (`nothing_to_write`), a Forecast `actual`, and a new cell in an archived metric or type (`archived_license_metric` / `archived_license_type`) are skipped with a reason code that has a translation key (`reports:licensing.import.reasons.*`); each skipped row carries its `metric`. One transaction, one event per card-year; it never creates a metric or type and never touches the card type.
- **Workspace transfer carries `LicenseMetrics` then `LicenseTypes`, applied by `_apply_license_catalogue`, and still imports a bundle written before metrics.** The rules are in `workspace-transfer.md`; `license_compat.py` (pure) reproduces migration 192 for an old bundle through the same `derive_type_metrics`, so a change to where 192 puts a type changes both.
